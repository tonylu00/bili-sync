# 关注备份与视频清理

添加视频源页面可以从数据库载入当前登录账号的关注 UP 主列表，或通过「从B站刷新关注列表」显式更新。首次载入时若没有备份，会请求B站。备份按登录账号 UID 隔离，只有完整且校验通过的列表才会替换旧快照；失败或不完整的响应不会清空备份。成功返回的空关注列表会保存为空快照。

打开「添加后留在本页并保留列表」，可以逐个选择 UP 主、预览投稿并设置不同的过滤规则。添加完成后保留候选列表和下载路径，刷新已添加标记，同时清空本次选择及过滤条件。此偏好保存在当前浏览器。

「视频清理」页面按主投稿体积、主投稿视频数、联合创作体积或协作视频数排序，支持搜索、查看视频详情和编辑此创作者的过滤规则。

- 视频数按 BV 号去重；体积按数据库记录的现有视频文件长度统计。同一文件或硬链接不重复计算，独立副本分别计算。体积不含封面、字幕、回收站内容和数据库之外的文件，也不等同于文件系统实际分配的块数。
- 联合创作单独列出每位创作者。协作体积包含共享视频，不能把各创作者的体积相加作为全库总量。
- 创作者规则按主投稿者 UID 保存，只作用于该 UP 主的主投稿，不作用于仅参与的联合创作。旧设置中的协作开关不再生效。视频仍须满足视频源规则。
- 规则用于后续自动下载，不会自动删除已有文件。可在视频详情中预览、删除。删除视频只解除当前来源的引用；其他来源仍使用或已独立保留的媒体不会删除。

视频详情中的主投稿者使用B站返回的 owner，联合创作者使用 staff 中各自的 UID 和名称，不再把订阅的协作者替换为主投稿者。数据库保留这些独立身份；生成的 NFO 分别写入各人的名字和角色，不把 UID 作为姓名或标题。已有 NFO 文件不会自动重写，旧记录中已经被覆盖的主投稿者需要重新获取视频详情才能恢复，不能从名字推断。

收藏夹修复保留可选的旧 ID 尾号查找。候选显示收藏夹名称、创建者 UID 和链接，选择并确认后才修改视频源。自动匹配优先使用已保存的创建者 UID，以及当前账号创建和关注的收藏夹。短 ID 无法唯一反推完整创建者 UID。

跨视频源共享媒体的实现与后续设计见 [按 BV 共享视频存储](shared-video-storage-design.md)。新下载按 BV/CID 复用一份完整媒体。清理页提供已有副本的扫描预览、保留路径、冲突详情和可恢复合并；数据库升级本身不删除文件。

迁移按主投稿者文件夹、联合创作者顺序、最先添加的合集/收藏夹选择保留位置。只有已完成且校验一致的副本能自动合并；不同质量保留为冲突。执行前备份数据库，保留媒体原地不动，其他来源通过应用内播放访问它。来源路径或模板变化只用于后续新媒体，不移动已登记的共享文件。来源专属封面/NFO保留，本阶段不创建外部媒体服务器的展示链接。
